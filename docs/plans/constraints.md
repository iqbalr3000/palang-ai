# Constraints

Rules every feature must respect. Carried over from the original technical spec (TSD, no longer
tracked) and later decisions, kept to what still holds after v0.1. Feature-level design lives in
`spec-*.md`; a change to anything here needs a record in `docs/decisions/`.

## Design principles

1. **Guards are runtime-agnostic.** `guards/` uses Web Standard APIs only: no `Bun.*`, no Hono, no
   `node:*` imports. It must pass `tsc` with `types: []` and has no runtime dependencies (ML stays
   optional and lives in `gateway/`).
2. **The request path never waits on the database.** Audit writes go through the async queue and
   are lossy under pressure, by design.
3. **Deterministic before probabilistic.** Regex + validation first, ML classifier second, LLM
   judge last.
4. **Monitor mode everywhere.** Every guard runs in `monitor` (log only) or `enforce`. `injection`
   defaults to `monitor` until its false-positive rate supports blocking.
5. **Secrets never persist.** The PII vault is a request-scoped `Map`, dropped after the response,
   never logged or serialized. Log decisions, not payloads.
6. **`pii-id` always fails closed**, regardless of the tenant's `failure_mode` (0008).

## Pipeline semantics

- Guards run **sequentially** in configured order (PII mask must precede anything that sends text
  elsewhere, e.g. an LLM judge).
- In `monitor` mode, `block` is downgraded to `flag` and recorded as `wouldBlock: true`.
- The first enforced `block` short-circuits the pipeline.
- Per-guard timeout. On timeout or exception: `fail_closed` → block with `guard_error`;
  `fail_open` → flag with `guard_error` and continue.
- Output: tool-call arguments are PII-restored **before** tool-policy evaluation.
- `injection` score = max over enabled layers; `≥ block_threshold` blocks, `≥ flag_threshold`
  flags.

## Public API contract

- OpenAI-compatible `POST /v1/chat/completions` (streaming and non-streaming), `GET /v1/models`,
  `/healthz`, `/readyz`. Unknown request fields are forwarded unchanged.
- Response headers: `x-palang-request-id`, `x-palang-decision` (`allow` | `flag`).
- Block (non-streaming): HTTP 400, OpenAI error shape — `error.type` `palang_policy_violation`,
  `error.code` the reason, plus `palang: { request_id, guard }`.
- Block mid-stream: one SSE `data: {"error": {...}}` event, then `data: [DONE]`, then close. Text
  already sent can't be recalled.
- Reason codes are snake_case and listed in `guards/src/core/reasons.ts`.
- The admin API (port 8081) is a separate listener and must never be publicly exposed; the
  dashboard calls it server-side only.

## Performance budgets

Single instance, measured with `bun run bench:gateway`.

| Metric | Budget |
|---|---|
| Guard overhead p95 (L1 injection + PII + tool policy + canary) | ≤ 10 ms |
| Added time-to-first-token p95 (streaming, no judge) | ≤ 100 ms |
| Memory per active stream | bounded by holdback + tool-argument cap |

The L2 classifier has no latency budget: it's opt-in per tenant and measured separately (0005).

## Security

- API keys: ≥ 32 bytes of randomness, stored as SHA-256 only, compared in constant time.
- Upstream API keys come only from config/env and are never returned by any endpoint.
- Request body limit (default 1 MB), upstream timeout (default 120 s), tool-argument cap
  (default 256 KB).
- External input is validated with Zod.
- Dependency audit in CI (`bun audit --audit-level=high`).

## Dependencies

Current stack — anything outside it needs the user's approval first and, if architectural, a
decision record.

| Concern | Choice |
|---|---|
| Runtime / tests | Bun, `bun test` (integration tests use the official `openai` SDK) |
| HTTP / SSE | Hono, `eventsource-parser` |
| Validation / config | Zod, `yaml` |
| DB | PostgreSQL 16, Drizzle ORM (+ `drizzle-kit` for `generate`), `postgres` |
| Logging | pino |
| ML (optional) | `@huggingface/transformers` (ONNX), an `optionalDependency` of `gateway/` |
| Dashboard | Next.js, Tailwind, shadcn/ui (Radix), Recharts |
| Tooling | TypeScript strict, ESLint + Prettier, Husky + lint-staged (0001) |

## Evaluation

- Every metric claim comes from `bun run eval` / `bun run bench:gateway`, with the report committed
  to `evals/results/`. README numbers are only updated from committed reports.
- Before and after any change to a guard, run both and report the before/after numbers. A drop in
  recall, a rise in false positives or latency is called out explicitly, never hidden.
- All PII in datasets and tests is synthetic, generated by scripts in `evals/src/generate/`.
- Data used to tune patterns or thresholds is never the data reported as held-out. Held-out sets
  are kept separate and their provenance documented.
- Public datasets: verify the license before committing; otherwise add a download script.

## Testing

| Level | Scope |
|---|---|
| Unit | Each guard, validators (valid **and** invalid cases), holdback buffer, tool-call assembler, pipeline runner |
| Property | Holdback buffer: random chunk splits of the same text produce identical restored output — required for any stream processor change |
| Integration | Gateway + mock-upstream through the official `openai` SDK, streaming and non-streaming |
| DB | Migrations + audit writer against a real Postgres 16 |
| Eval | `bun run eval` |

Done for any change: `bun run typecheck && bun run test` pass, no new `any`, new behavior covered by
tests. Guards are written test-first.
